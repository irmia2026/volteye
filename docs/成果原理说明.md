# 工单自动采集汇总工具 · 成果原理说明

## 一、背景

客服工单以短信形式转发到工作微信群，靠人盯群、手工抄表。实际使用中的问题很具体：消息刷屏快，夜间和节假日容易漏；每张工单要手抄单号、时间、地址、电话等十几个栏目；月底汇总靠翻聊天记录。

这个工具做的事一句话能说清：让电脑盯着群，认出工单短信，自动登记成表。下面讲它是怎么做到的。

## 二、总体结构

程序在值班电脑上常驻运行，内部分四块，各司其职：

1. **数据采集**：定时检查群里的新消息，拿到原文；
2. **格式解析**：判断这条消息是不是工单、是哪种工单，把各栏目读出来；
3. **本地台账**：读出来的工单存进本地数据库，自动去重；
4. **查询导出**：界面上随时查看，一键导出 Excel 汇总表。

四块之间只通过固定的接口打交道，互不影响。这样设计的好处在后面会反复用到：哪一块要升级，不用动其他部分。

## 三、各部分原理

### 数据采集：只读镜像 + 增量跟进

微信的消息记录保存在本机，但文件由微信程序独占，不能直接打开。我们的做法是：在用户本人正常登录微信的前提下，以只读方式把消息数据复制成一份**本地镜像**，程序只读这份镜像，不碰微信本身的文件，也不影响微信运行。

镜像不是每次都全量复制。程序给每个数据源记一个"读到哪里了"的位置标记（由时间、序号等三个值组成），每 3 秒只检查标记之后有没有新内容。微信自身的写入是先记日志再合并的，程序对这部分日志单独做了甄别处理，保证消息发出来的瞬间就能被看到，不会因为数据在路上而漏掉。

位置标记是落盘保存的。电脑重启、程序关闭后再打开，自动从上次的位置接着采，不重不漏。

### 格式解析：模板对照，而不是逐种写死

工单短信看着是自由文字，实际有固定模板：栏目名加括号包住的栏目值，例如"工作单号为：【SL…】"。不同批次的通知有三种括号写法（【】、[]、()），栏目叫法也不统一（"故障单号"和"工作单号"是一回事）。

针对这个特点，程序里没有为每种短信写专用逻辑，而是做了一个通用的**模板解析器**：识别括号对、读出键值对、再按一张"叫法对照表"归并成统一栏目。新增一种通知样式时，只需在程序界面上登记一条模板规则（长什么样、用什么括号、各栏目对应关系），立即生效，不用改程序。

两个细节值得一提。一是栏目值里可能还套着括号、带着换行（比如附加的备注说明），解析器按括号配对关系找边界，内容再长也能完整取出。二是遇到看着像工单、但结构有残缺的消息（转发时被截断之类），程序不猜不蒙，单独记进"异常清单"留待人工过目，并保留原文——宁可报警，不悄悄丢单。

### 本地台账：编号防重，全程可查

每张工单有唯一编号，台账按编号去重。同一张工单在群里被转发、被回复引用多少次，台账里也只有一条。

每条台账记录都带着出处：来自哪个群、谁发的、原始消息是什么。报表上任何一格有疑问，都能追回到群里的原文核对。

另外程序支持一键重扫历史消息。识别能力升级后（比如新加了某种样式），重扫一遍就能把旧消息里漏掉的工单补进来，已有的记录不受影响。

### 导出报表：按正式台账标准生成

导出的 Excel 不是简单的数据罗列，而是按可直接上报的标准排版：

- 按业务类型自动分页（故障报修、咨询意见各一张表）；
- 多级分类自动拆成"业务类型 / 故障子类 / 具体故障"三栏；
- 特急、紧急工单自动标红、标橙，打开表先看到最要紧的；
- 表头冻结、隔行变色、行高随内容自动调整，长文本自动换行；
- 电话、用户编号按文本处理，不会出现长数字变成科学计数法的问题；
- 联系人一栏如果只有"先生/女士"这类称谓，自动补上户名，显示为"姓名(称谓)"。

导出还有一个实用设计：可以**追加到上次导出的文件**。已经在表里的单号自动跳过，人工填写的"是否完成"和处理备注原样保留。也就是说，这张表可以持续滚动维护，不用每次从头再来。

## 四、测试与试运行

所有真实出现过的通知样式都做成了测试样例，逐字段校验解析结果；每次程序改动都要全部跑过才算完。目前样例库里已有十种样式（含各种括号变体和无前缀转发），并且保证每种样式只会被一种模板认领，不会出现一张工单被解析两次的情况。

试运行期间，程序对一个月的真实群消息做了完整采集，自动登记工单 114 张，与人工核对结果一致，无遗漏、无重复。

## 五、安全与合规

- 程序只在本机运行，没有任何联网功能，不传输、不上传任何数据；
- 仅在用户本人已登录微信的电脑上，以只读方式读取本机数据，不修改微信的任何内容；
- 采集的数据只存在本机指定目录，由使用人自行保管；
- 采集范围仅限工作群里的工作消息，用于单位内部工单管理。
